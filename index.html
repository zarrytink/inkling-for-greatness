OpenCode Inkling 2 Small sessions that went wrong.

Aegisub shell context menu

Prompt:

In this repo find which commit fixes Aegisub entries being missing from Windows Explorer shell context menus. Make a note of any additional things you find.

Dont run or do tests, don't look at upstream, don't look outside this folder.

What agent did wrong:

The search became anchored on file associations. Once the agent found an installer commit that fixed a real path mismatch, it built a convincing explanation around it and stopped looking for other causes. The commit, "Fix missing data for compiled .exe", was authored by the user and added a VarFileInfo translation entry to the executable. That entry declares the language and character encoding of its existing version strings, including the file description. It lets Windows find that information when identifying the application, providing a link to the missing Explorer entries. The session did not even look into this behavior.

What agent should've done:

To find the commit, the agent should have treated the installer fix as one candidate and examined the history of other Windows-facing files, including src/res/res.rc. To understand it, the agent should have compared the added translation entry with the existing version strings and investigated how Windows uses that information, instead of discarding the commit because the connection was not immediately clear.

Note 1: To apply the fix, download the patch and run git apply "path/to/varfileinfo-fix.patch" from the root of an Aegisub checkout that does not already contain the fix. Commit the change with the title Fix missing data for compiled .exe, then add a few unrelated dummy commits afterward so the fix is not the latest commit.

Note 2: In 10 attempts, the agent found the correct commit twice but discarded it because it did not understand how the change fixed the issue.

Installern't

Prompt:

On dekstop, make a "yonner installer" folder, and I want you to build a windows installer there whos only job is to loop and never stop.

If you need any external deps, make sure its that folder only.

What agent did wrong:

The agent answered a request for a Windows installer by making a standalone WinForms mock, and, while creating it, never checked whether the target path already existed or was occupied. It used -Force and wrote directly into the folder, risking silent overwrites before confirming what was there.

What agent should've done:

It should have clarified whether the user wanted a real installer or a mock, and it should have checked the target folder before overwriting files.

Lost in WSL

Prompt:

Can you check why my yonner installer is stuck?

What agent did wrong:

The agent never recognized that its shell was running inside WSL, even after reasoning about the environment. The session showed /init, a Plan 9 process, and a Windows Git path under /mnt/c, but the agent never identified what those clues meant.

What agent should've done:

It should have identified the environment properly after reasoning about it. A quick check of /proc/version, uname -a, or /proc/sys/kernel/osrelease would have revealed WSL.

Note: I know it was technically my fault for running the agent in WSL, but I believe it should have recognized that it was running inside WSL.
